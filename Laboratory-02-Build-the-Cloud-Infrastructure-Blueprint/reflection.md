# Mission Reflection

## 1. Which cloud infrastructure component do you think is the most important? Why?

For me, the compute resource is one of the most important components of cloud infrastructure because it provides the processing power needed to run applications, services, and other system processes. Without compute resources, the other infrastructure components would not be able to perform useful tasks. In this laboratory, I was able to see how a virtual machine can provide the computing environment needed for different activities.

## 2. How does Linux support cloud computing?

Linux supports cloud computing by providing a stable and flexible operating system for servers and virtual machines. It also provides many command-line tools that allow administrators and cloud engineers to monitor system resources, manage files, configure networks, and inspect system information. Using the KillerCoda environment helped me understand how Linux is used in a cloud-based server.

## 3. Why is technical documentation important before deploying infrastructure?

Technical documentation is important because it records the resources, configurations, and decisions related to an infrastructure design. It helps engineers understand the current environment and can also make troubleshooting and future maintenance easier. Proper documentation can reduce mistakes before actual cloud services are deployed.

## 4. What new skills did you learn during this laboratory activity?

I learned how to investigate a Linux virtual machine using commands such as `lscpu`, `free -h`, `df -h`, and `ip addr`. I also learned how to identify compute, storage, networking, and operating system resources and compare similar services from AWS, Azure, and Google Cloud. In addition, I practiced creating a cloud infrastructure diagram and organizing technical files using Markdown and GitHub.

## 5. How has your GitHub portfolio improved after completing this mission?

My GitHub portfolio became more organized and complete after adding the Laboratory 02 folder and its supporting documentation. It now contains system investigation results, cloud infrastructure information, a provider comparison, screenshots, and a cloud architecture diagram. The activity also helped me understand the importance of using clear file names, proper folder organization, and meaningful commit messages when maintaining a technical portfolio.
